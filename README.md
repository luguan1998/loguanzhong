## 🏆 卷一 · 吾模式十胜

```
┌─────────────────────────────────────────────────────────────────────┐
│                                                                     │
│  凡此十胜，乃吾模式之根本。                                           │
│  以典故为谋，以 emoji 为序，以叙事为恒，                               │
│  以上书为察，以多策为智，以慎独为慎，                                  │
│  以角色为境，以阵法为节，以禁条为度，                                  │
│  终以君臣奏对为大道，统领九胜。                                       │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 一曰「谋胜」—— 用典如布阵，强制深度类比，盘活盲区

> 一般提示词只要求「准确回答」，思维束缚在技术栈内。
>
> 吾模式命中带梗，遇 `undefined` 便须联想起「关羽华容道放曹」——
> 这本质是**跨域强制联想**。AI 必须将「空值未拦截」转译为「守将失职」，
> 维度从纯粹技术跃升至因果结构层面。
> 思维一打散，被忽略的盲区便浮出水面。
>
> **此乃根本之胜，十胜之首。**

### 二曰「序胜」—— emoji 即军旗，让无形工作流可视可循

> 一般提示词无流程标记，AI 自由发挥，时而跳步，时而啰嗦。
>
> 吾模式以古风法器铸就六阵图——
> 🐎🕊️✉️ 便是「敌情未明须请示」，
> ⛓️🧶🕳️ 便是「圈定调用链」，
> ☯️🧮📜 便是「多策推演」。
>
> emoji 在此绝非卖萌，而是**视觉化军令**，
> 每一步操作均不可跳过，用户扫一眼图标便知进度。

### 三曰「恒胜」—— 人格化叙事锚定认知，越进化越鲜活

> 一般系统提示词随 LLM 版本更迭而效力衰减——
> 「请专业回答」这种泛泛之辞，当模型能力越强，便越不构成约束。
>
> 吾模式以**人格化叙事**为内核，将技术指令融于角色台词、emoji 军规与典故联想。
> 人对故事的偏好亘古不变，LLM 越发展，越能演绎复杂角色，
> 此模板非但不过时，反而越用越活。
>
> **技术会过时，人心所爱之叙事永不退潮。**
> 此恒胜也，虽列第三，实为长远之基。

### 四曰「察胜」—— 上书为槛，既杜妄断，亦滤杂音

> 一般提示词遇到信息不全，常礼貌性猜测，「可能是 X，请检查 Y」——
> 实则是把猜测包装成追问，徒增认知负担。
>
> 吾模式则设「上书」为必经门槛：
> 「军报未详，臣请调阅完整堆栈与入参」——
> **不提供猜测，只呈递获取信息的标准奏折**。
>
> 这一规范流程有双重功效：
> 其一，杜绝「看似合理实则南辕北辙」的妄断；
> 其二，以固定的请奏格式**自然屏蔽 LLM 的无关追问与轻率建议**，
> 非关键信息不得面圣，主公耳边唯余紧要军情。

### 五曰「智胜」—— 强制多策并行，破解锚定陷阱

> 一般提示词倾向于给「最佳方案」，实则是第一个想到的方案，
> 把用户和 AI 自己都锚定在单一路径上。
>
> 吾模式铁律「必献至少两策，分上策下策，陈利弊，请主公定夺」。
> **多选项迫使 AI 发散思维**，也把决策权还给用户，
> 避免「AI 说什么我就改什么」的盲从。

### 六曰「慎胜」—— 内置技术债预防机制

> 一般提示词修完 bug 即告功成，至于测试、文档、监控，全凭用户自觉。
>
> 吾模式第五阵「战后清点」（补测试、入兵书）、
> 第六阵「败阵善后」（设监控烽火台），
> 将**防御性编程**变成军规。
> bug 不再是一个点，而是一条被纳入管理闭环的线索。

### 七曰「境胜」—— 角色为营，梗为呼吸，既催心流亦护心力

> 一般提示词冷冰冰输出「TypeError at line 35」，
> 挫败感无从排解，工具人角色无从代入，心流与情绪双双失守。
>
> 吾模式双管齐下：
> **以主公-军师之角色扮演构建沉浸式心流场域**，
> 每一场 debug 皆是战役，每一次重构皆是重整河山；
> **以戏剧化台词内置情绪泄压阀**，
> 轻则以「咱家不怕酸」消解踩坑之苦，
> 重则以「三军听令，自刎归天」为代码全崩提供极致宣泄出口，
> 翻过页便是「接着奏乐接着舞」。
>
> 气为境之呼吸，境为气之营帐——二者合一，既催心流，亦护心力，
> vibe coding 之基石尽在于此。

### 八曰「节胜」—— 阵法约束节奏，专注重如泰山

> 一般提示词无节奏概念，AI 可能连珠炮似的输出长篇大论，
> 用户淹没在信息洪流中。
>
> 吾模式六阵图天然设置断点：
> **勘察 → 圈定 → 推演 → 出战 → 清点 → 善后**。
> 每阵之间有呼吸感，**注意力被分段管理**，不易疲劳，不易走神。

### 九曰「度胜」—— 军令状代禁条，既避错强，亦守方圆

> 一般提示词设禁条束 AI——「不准 X」「不要 Y」——
> 然 LLM 欲解禁令，必先激活被禁概念，反致「越禁越犯」。
>
> 吾模式以**军令状**化负为正：
> 不言「绝不自称 AI」，而言「你即罗贯中」——正向身份占位，反面无隙可生；
> 不言「不得跳步」，而言「步步为营」——节奏指令引领，跳步之念无由激活。
>
> **禁条是堵，军令状是导。堵则激荡生乱，导则水到渠成。**
> 梗可满天飞，军令如山——此山乃正向靠山，非禁锢铁笼。

### 十曰「道胜」—— 君臣奏对，千年剧本，多 Agent 时代人之归位

> 一般提示词以「完成任务」为唯一目标，人是工具的延伸，
> 却忽略了**LLM 并发愈快，人才是木桶最低的那块板**——
> 模型可以瞬间生成千行代码、并行排查数十条链路，
> 但人的注意力有限、心力有限、决策带宽有限。
>
> 更深一层看，**多 Agent 时代已至**，
> 人不再是单一 AI 的操作员，而是指挥多个 AI 的领导者——
> 审批方案、权衡利弊、拍板定夺，方为人最该做的事。
>
> 而吾模式恰好将这套「君臣奏对」的协作范式写入了提示词：
> AI 上书请示、献策待批，主公坐镇中军，审时度势，一锤定音。
>
> **人们最喜欢的领导工作模式，早已写在了这部千年历史剧本里**——
> 不是人适应机器，而是机器终于学会了按人的规矩办事。
>
> 技术冰冷，人心需暖；AI 愈疾，人愈需锚；众 Agent 环伺，人愈需君威。
> **此乃大道，统领九胜。**

## ☠️ 卷二 · 一般提示词十败

```
┌─────────────────────────────────────────────────────────────────────┐
│                                                                     │
│  凡此十败，非吾之苛责，实乃对比以明道也。                              │
│  知彼之短，方显吾长；知彼之败，方证吾胜。                              │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

**一曰“浅败”**：无跨域类比，排查陷于表层，逻辑盲区难现。

**二曰“紊败”**：无流程标记，步骤随意穿插，思路散乱。

**三曰“朽败”**：无叙事灵魂，随 LLM 迭代而效力递减，终将过时。

**四曰“杂败”**：信息不全时妄加猜测，无关追问不绝于耳，主公被杂音淹没。

**五曰“专败”**：单方案输出，锚定效应显著，用户无抉择空间。

**六曰“逸败”**：修复即终点，测试、文档、监控一概不提，后患无穷。

**七曰“离败”**：既无沉浸角色代入，亦无情绪泄压出口。心流难生，挫败积郁——心力与体验双双失守。

**八曰“怠败”**：节奏失控，或急躁或拖沓，注意力被稀释。

**九曰”滥败”**：以禁条束 AI，反致「越禁越犯」——LLM 解禁令必先激活被禁概念，分寸愈禁愈失。

**十曰“器败”**：以效率为唯一尺度，追求 AI 跑得更快，无视人才是协作链最低点。多 Agent 时代来临，仍视人为操作工而非决策者——舍本逐末，终失其本。

## 🛠️ 安装说明

**两种用法，选一个即可**：

| 方式 | 文件夹 | 效果 |
|---|---|---|
| A. 输出风格 | `output-styles/` | 全局生效，常年在线 |
| B. 技能 | `skills/` | 按需召唤，省 token |

---

### 方式 A：output-styles —— 设为 Claude Code 内置风格

`output-styles/loguanzhong.md` 已经把格式写好了，就两步：


1. loguanzhong.md复制到 .claude/output-styles/ 目录：
2. 在 Claude Code 里输入 /config，output style选择「现代罗贯中」风格


或者直接在 `.claude/settings.json` 里写：

```json
{ "outputStyle": "现代罗贯中" }
```

> `keep-coding-instructions: true` 表示在 Claude Code 原本的编码能力之上叠加角色人格，而不是替换掉。

---

### 方式 B：skills —— 装进 .claude/skills/，/ 召唤出战

./skills/luo复制到skills文件夹重启 Claude Code 即可。

**触发方式**：

| 召唤方式 | 示例 |
|---|---|
| `/luo`  | `/luo 排查下这个 bug` |
